DeepSeek V4.1 Flash Gets 35% Better in Five Weeks, Without a New Name

On October 17, DeepSeek pushed DeepSeek-V4.1-Flash-1017, a "minor update" to the open-weight model it launched on September 10. The scores on agent and coding benchmarks jumped by double digits, outputs got shorter, and the API name, the price and the MIT license stayed the same. Here is what changed, what the numbers do not say, and how to try it on your own work.

A "Minor Update" With Major Numbers

AI labs usually save big jumps for big launches, with a new version number, a livestream and a blog post. DeepSeek did the opposite.

On October 17, 2026, it replaced the model behind its deepseek-flash API name with DeepSeek-V4.1-Flash-1017. The suffix is simply the date: October 17. The Hugging Face model card calls it a "minor update" that "reduces task execution time and output length."

Yet the model it replaces is only five weeks old. V4.1-Flash launched on September 10 as the smallest model in DeepSeek's new architecture family, with native image understanding. In those five weeks, its score on Terminal-Bench 4.0, a test of agents working in a real command line, went from 31.2 to 42.3.

What Changed: The Benchmarks

DeepSeek published a before-and-after table in its change log. Here are the lines that matter most for coding and agent work.

The pattern is clear. The biggest gains are on long, multi-step agent tasks: driving a terminal, building a program, automating a workflow. Pure knowledge tests moved less. This update was tuned to make the model a better worker, not a better quiz contestant.

Two details from the change log are worth knowing. Terminal-Bench 4.0 was run inside the Claude Code framework, and DeepSWE with Mini-SWE-V2. So these are scores of the model plus a specific agent harness, not of the model alone.

Hidden Win

Shorter Answers Are a Price Cut

DeepSeek says the update cuts both task execution time and output length. That sounds like a detail, but on an API you pay per output token. If the model reaches the same result with fewer tokens, each task costs less, even though the price per token did not change. For agents that run hundreds of steps a day, this is often worth more than a few benchmark points. DeepSeek did not publish exact figures, so measure it on your own tasks.

What Stayed the Same

  • The API name. It is still deepseek-flash. If you call it, you are already on 1017, with no code change.
  • The price. The change log says calling method and pricing are unchanged. At the September launch, off-peak input started at about 15 cents per million uncached tokens, according to SiliconANGLE. Check the official pricing page for current peak and off-peak rates.
  • The license. The weights are on Hugging Face under the MIT license, one of the most permissive licenses in software. You can host, modify and use the model commercially.
  • The apps. The DeepSeek web and mobile apps were updated to 1017 too.
  • The context window. Several model directories list a context of about 1 million tokens for V4.1-Flash. Third-party listings also describe it as a large mixture-of-experts model of about 552B total parameters with only a small fraction active per token. DeepSeek's change log does not repeat these figures, so treat them as reported.

Built for Agents, Not Chat

The clearest sign of where DeepSeek is heading is who it tuned this update for. The change log names three agent products:

  • DeepSeek Harness, DeepSeek's own agent runtime. Version 0.2.1-rc.1 or later is recommended.
  • CodeBuddy, Tencent's coding assistant.
  • WorkBuddy, Tencent's desktop office agent, which has offered V4.1-Flash since September 10.

DeepSeek also offers two tools that agents need constantly. The Search API returns up to 50 ranked web results per query, and the Fetch API turns a web page into Markdown. According to SiliconANGLE, each costs 75 cents per 1,000 successful requests, and calls made through DeepSeek Harness, Claude Code or OpenAI Codex are free until November 1.

That last point is a strategic choice. DeepSeek is not asking developers to switch tools. It is offering to sit inside the tools they already use.

The Fine Print

Self-reported scores. Every number in the table above comes from DeepSeek's own testing. No independent lab has published results for 1017 yet. Benchmarks also depend heavily on the agent framework used to run them.

Claude Opus 5 Still Leads Overall

On DeepSWE, the 1017 update edges past Claude Opus 5, 77% against 74%. That is the headline some outlets ran with. But according to SiliconANGLE, Claude Opus 5 still leads on 7 of the 11 benchmarks DeepSeek published, with a gap of almost 14 points on Humanity's Last Exam. A cheap, open Flash model is closing the gap on specific tasks, not overtaking frontier models across the board.

Reliability

On October 15, two days before the update, the DeepSeek API suffered a nearly five-hour outage, one of its worst this year according to Yicai Global as cited by SiliconANGLE. DeepSeek apologized, issued credits based on the previous week's spending, and said it would remove single points of dependency. Some experts pointed to a shortage of computing capacity.

Data Location

For many companies, sending code or client data to a China-based API is a compliance problem, whatever the benchmark scores. This is where the MIT weights matter: you can run the model on your own servers or through a cloud provider in your region, and keep your data where your policies require. Use Cases

Where V4.1-Flash-1017 Makes Sense

  • Teams running coding agents at scale: high-volume tasks where a cheaper model with shorter outputs changes the monthly bill.
  • Companies that must self-host: MIT weights mean no API dependency and no data leaving your infrastructure.
  • Developers already on deepseek-flash: you got the upgrade automatically, so re-check your agent's behavior and costs.
  • Product builders: a strong open model as a fallback or router target next to a closed frontier model.
  • Researchers: an open model that improves this fast is a useful reference point for fine-tuning experiments.

How to Try It

1. Through the API

The DeepSeek API is compatible with both the OpenAI and the Anthropic formats. With the OpenAI Python SDK, only the base URL and the model name change:

# pip install openai from openai import OpenAI client = OpenAI(api_key="YOUR_DEEPSEEK_KEY", base_url="https://api.deepseek.com") resp = client.chat.completions.create( model="deepseek-flash", # now served by V4.1-Flash-1017 messages=[{"role": "user", "content": "Explain this stack trace and propose a fix: ..."}], ) print(resp.choices[0].message.content)

For tools that speak the Anthropic format, the documentation lists https://api.deepseek.com/anthropic as the base URL. The API also exposes a thinking option and a reasoning_effort setting for harder tasks.

2. In the Apps

The free DeepSeek web and mobile apps already run 1017. This is the fastest way to get a feel for it, but do not paste confidential data there.

3. Self-Hosted

Download the weights from Hugging Face and serve them on your own hardware or with a cloud provider. This removes the data-location issue and the outage risk, but a model of this size still needs serious GPUs. For smaller local setups, see our local LLM tools.

4. Test It Fairly

Take ten real tasks from your backlog. Run them through V4.1-Flash-1017 and through the model you use today, with the same agent framework. Measure three things: was the task solved, how many tokens did it use, and what did it cost. A benchmark gain is only real if it shows up on your own work.

DeepSeek V4.1-Flash-1017 is a big upgrade disguised as a small one. Double-digit gains on agent benchmarks, shorter outputs, same price and free MIT weights. It does not beat Claude Opus 5 overall, and the scores are self-reported, but it is worth a side-by-side test on your own coding and agent tasks.

Frequently Asked Questions

What is DeepSeek-V4.1-Flash-1017?
It is an updated version of DeepSeek's V4.1-Flash model, released on October 17, 2026. It replaces the September 10 version behind the deepseek-flash API name and in the DeepSeek apps, with higher scores on agent and coding benchmarks and shorter outputs.
Do I need to change my code?
No. The API name deepseek-flash now points to 1017, and the calling method is unchanged. If you rely on stable behavior, re-test your prompts and agents, because the model under the name changed.
Did the price change?
No. DeepSeek's change log says pricing is unchanged. Because outputs are shorter, the cost per task may actually go down.
Is it open source?
The weights are published on Hugging Face under the MIT license, which allows commercial use, modification and self-hosting.
Is it better than Claude Opus 5?
On DeepSWE v1.1 it scores 77% against 74% for Claude Opus 5, according to DeepSeek. But Claude Opus 5 still leads on 7 of the 11 benchmarks DeepSeek published, including a gap of almost 14 points on Humanity's Last Exam.
Can I use it with Claude Code?
DeepSeek offers an Anthropic-compatible API endpoint, and its Terminal-Bench 4.0 score was measured inside the Claude Code framework. According to SiliconANGLE, Search and Fetch API calls made through Claude Code, OpenAI Codex or DeepSeek Harness are free until November 1.

My Take

As a network engineer, I learned long ago to watch trends, not snapshots. One good benchmark score tells you little. A curve that keeps rising tells you a lot.

That is what stands out here. DeepSeek did not need a new version number to gain 11 points on Terminal-Bench. It shipped a quiet update five weeks after launch, and the model is noticeably better at the work agents actually do. Closed labs ship big launches; open labs are shipping fast iterations, and the gap on specific tasks is shrinking month after month.

My advice: do not migrate everything because of one table. But if you run coding or automation agents, add an open model like this one to your test set, measure cost per solved task, and keep your data policies in mind. If an open model you can host yourself keeps improving this fast, paying frontier prices for every single task gets harder to justify.
